# Feedback ranking
Ranking version feedback-v1 uses archived owner decisions only; no resume, demographics or contact attributes enter training. Three distinct posting identities are required per rule. Applied decisions add weak function/level/workplace weights. Not-relevant decisions require an explicit dimension to contribute negative weights. Old/unavailable decisions contribute source freshness penalties only. Generic dismissal does not generalize. Rule weights are capped at six and the total adjustment at fifteen in either direction. No job is hidden or newly admitted by learning.

Recommended ordering scores the filtered result in PostgreSQL and returns only the requested 25-row page; chronological order and job ID break ties. Emailed views retain email-time tie ordering. Newest ordering remains available. Database scoring still examines eligible rows: the bound applies to rows returned to Python, not the database scan. Explanations and private application summaries are computed only for the returned page.

Immutable version snapshots expose counts and explanations. Pause disables effects; reset starts a new evidence window without deleting archives; restore pins an owner-owned previous version; resume unpins and incorporates subsequent feedback. GET requests and report reads use saved snapshots and never train, acquire a learning advisory lock or create a version. A new owner has neutral, unsaved version 0 until the first feedback publication or an explicit resume/reset action.

Models publish deterministically in the same owner-scoped transaction as a new archive decision, or an explicit reset/resume command. A training failure rolls back that mutation. The existing learning advisory lock serializes publications and controls. Pausing disables ranking effects but permits subsequent feedback snapshots; pinning holds a previous snapshot until resume. Repeated unchanged evidence reuses the current version. If source metadata changes and later returns to earlier values, a linked immutable version records the return without selecting an older active ID. The model's evidence fingerprint is metadata, not a new ranking feature.

Direct archive imports must explicitly call `refresh` under the intended private owner context after their transaction's inserts. Ordinary source refreshes do not retrain owner models; the next feedback publication or explicit resume incorporates changed source metadata. No collector identity gains access to private owner feedback. No additional worker, schema migration or permissions are required.

This is bounded statistical feedback, not self-modifying code or autonomous submission. Source counts describe reviewed listings, not unbiased source-wide quality estimates.

Feedback-v2 adds Spam and Suspected fake posting flags. Emailed jobs archive and lock using the existing workflow. Three distinct reported postings from a source produce a capped source-only penalty, explicitly described as unverified user reports. Reports never assert proven fraud or infer role preferences from these flags. Prior model snapshots remain restorable.
